Publicação incremental usa `compose.staging.yml`, app `dns-panel-rpz-app:feed-url-20261110`
e nginx `dns-panel-rpz-web:sidebar-clean-20261110`. Os Dockerfiles de overlay estão
versionados e dependem das imagens-base locais indicadas em seus `FROM`; não são
uma cadeia independente de build em uma máquina vazia. O nome da tag final é
histórico e inclui as melhorias posteriores da sessão.

Comandos usados nas publicações visuais:

```sh
docker compose -f compose.staging.yml build app
docker compose -f compose.staging.yml up -d --no-deps app
docker compose -f compose.staging.yml exec -T nginx nginx -s reload
```

O reload do nginx atualiza o encaminhamento após recriar o app. Nas últimas
publicações foram atualizados somente app/nginx, sem reiniciar os resolvers clientes.
O commit solicitado é local; envio ao remoto não faz parte desta etapa.
