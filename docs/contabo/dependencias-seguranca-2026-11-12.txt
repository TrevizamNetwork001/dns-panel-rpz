Dockerfile: docker/Dockerfile.security-overlay. O build usa o código da imagem
selecionada para gerar o autoload e troca apenas vendor, composer.json e lock.
Isso preserva o código específico das imagens web e de processamento. Não é o
Dockerfile de instalação em uma máquina vazia; para isso use o Dockerfile completo
e o procedimento INSTALACAO-NOVA.md, que também instala o lock corrigido.

Configuração de publicação
O compose.staging.yml versionado registra as imagens corrigidas. O runtime ainda
usa a base /opt/dns-panel-rpz/compose.staging.yml com o override persistente
/root/ui-admin-release/compose.ui-admin.yml; o override inclui os sete serviços PHP.
Não executar somente o compose antigo de /opt, pois isso selecionaria imagens
anteriores. O checkout de /opt não foi alterado nesta entrega.

Comando do painel:
 docker compose --project-directory /opt/dns-panel-rpz \
   -f /opt/dns-panel-rpz/compose.staging.yml \
   -f /root/ui-admin-release/compose.ui-admin.yml \
   up -d --no-deps --no-build --wait --wait-timeout 120 app

Após trocar PHP-FPM, recarregar nginx e limpar o cache de rotas da aplicação para
não preservar matchers compilados anteriores à correção. Os demais serviços são
recriados sem dependências; os primários IPv4/IPv6 são atualizados separadamente.
Nenhum comando é executado nos DNS dos clientes.

Reversão
As imagens-base anteriores permanecem no Docker. O override anterior está em
/root/security-review/compose.before-security.yml. Com o compose ORIGINAL de /opt,
esse override volta a selecionar a imagem web anterior e as imagens originais dos
workers/primários. Recriar os serviços e recarregar nginx se uma reversão for
necessária. Reverter reintroduz os avisos de dependências; é apenas contingência.

Prevenção
- O workflow de testes passa a executar composer audit --locked em cada push/PR.
- O teste de instalação independente também é disparado por mudanças nos arquivos
  de dependências PHP e Node.
- Não foram adicionados 2FA ou chaves CAPTCHA: são melhorias separadas. A correção
  dos avisos conhecidos não equivale a garantir ausência de outras vulnerabilidades.
